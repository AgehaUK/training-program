# 要件定義書: ダッシュボード画面

## 目的

構造化済みの故障データを集計・可視化し、故障傾向・コスト・トレンドを一目で把握できるようにする画面。
設備設計者が設計改善の根拠を得たり、工場管理者が投資判断を行うための分析基盤となる。

## 機能

| # | 機能 | 説明 | v1からの変更点 |
|---|------|------|--------------|
| 1 | 故障モード別内訳表示 | 故障モード（劣化、破損、動作不良等）の発生件数を円グラフで表示する | 新規 |
| 2 | 月次トレンド表示 | 月別の故障発生件数の推移を折れ線グラフで表示する | 新規 |
| 3 | コストTOP10表示 | 故障コストが高い設備・部品のランキングを棒グラフで表示する | 新規 |
| 4 | 示唆出し | 分析結果からLLMが改善施策の示唆を自動生成し表示する | 新規 |
| 5 | フィルタリング | 期間・設備名・故障モード等でデータを絞り込む | 新規 |
| 6 | サマリー統計 | 総故障件数、総コスト、平均停止時間等のKPIを表示する | 新規 |

## Input / Process / Output

| 機能 | Input | Process | Output |
|------|-------|---------|--------|
| 故障モード別内訳表示 | DBの構造化済み故障データ全件（またはフィルタ後） | 故障モード別にCOUNT集計 | 円グラフ（故障モード名: 件数の内訳） |
| 月次トレンド表示 | DBの構造化済み故障データ全件（またはフィルタ後） | 発生日を月単位でGROUP BY、件数をCOUNT | 折れ線グラフ（X軸: 月、Y軸: 件数） |
| コストTOP10表示 | DBの構造化済み故障データ全件（またはフィルタ後） | 設備名または部品名ごとにコストをSUM、降順TOP10 | 棒グラフ（X軸: 設備/部品名、Y軸: コスト合計） |
| 示唆出し | 集計済みの分析結果（故障モード内訳、トレンド、コストTOP10） | 集計データをLLM APIに送信し、改善施策の示唆を生成 | 示唆テキスト（例:「温度センサー故障が全体の30%。定期交換サイクルの見直しで年間XX万円削減可能」） |
| フィルタリング | ユーザーが選択した期間・設備名・故障モード | フィルタ条件でDBをクエリし、対象データを再取得 | フィルタ適用後の全グラフ・KPIの再描画 |
| サマリー統計 | DBの構造化済み故障データ全件（またはフィルタ後） | 総件数COUNT、コストSUM、停止時間AVG を算出 | KPIカード（総故障件数、総コスト、平均停止時間） |

## UI状態遷移

| 要素 | 対応機能 | 状態 |
|------|---------|------|
| KPIカード群 | サマリー統計 | ローディング（データ取得中）→ 表示（数値表示）→ 更新中（フィルタ変更時） |
| 円グラフ | 故障モード別内訳表示 | ローディング（初期）→ 描画済み → 更新中（フィルタ変更時）→ 再描画 |
| 折れ線グラフ | 月次トレンド表示 | ローディング（初期）→ 描画済み → 更新中（フィルタ変更時）→ 再描画 |
| 棒グラフ | コストTOP10表示 | ローディング（初期）→ 描画済み → 更新中（フィルタ変更時）→ 再描画 |
| 示唆カード | 示唆出し | ローディング（LLM呼出中）→ 表示（示唆テキスト表示）→ 更新中（フィルタ変更時） |
| フィルターバー | フィルタリング | 初期値（全期間・全設備・全モード）→ ユーザー選択中 → 適用済み |
