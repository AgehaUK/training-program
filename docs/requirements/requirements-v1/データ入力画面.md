# 要件定義書: データ入力画面

## 目的

現場保全担当者が自由記述の故障報告テキストを入力し、LLMによって構造化データ（JSON）に変換・確認・保存する画面。
故障報告の「入口」として、非構造化データを分析可能な構造化データに変換する役割を担う。

## 機能

| # | 機能 | 説明 | v1からの変更点 |
|---|------|------|--------------|
| 1 | テキスト入力 | 自由記述の故障報告テキストを入力する | 新規 |
| 2 | LLM構造化 | 入力テキストをLLM APIに送信し、構造化JSONを生成する | 新規 |
| 3 | 構造化結果表示 | LLMが抽出した構造化データを表示する | 新規 |
| 4 | 構造化結果の編集 | 構造化結果を人間が確認・修正できる | 新規 |
| 5 | データ保存 | 確認済みの構造化データをDBに保存する | 新規 |
| 6 | サンプルデータ投入 | デモ用のサンプル故障報告テキストを一括で投入し構造化する | 新規 |

## Input / Process / Output

| 機能 | Input | Process | Output |
|------|-------|---------|--------|
| テキスト入力 | ユーザーが入力する自由記述テキスト（例:「2023年12月5日、温度センサー故障。停止3時間、部品代5万円」） | テキストエリアに入力値を保持 | 入力済みテキスト（構造化ボタンが有効化） |
| LLM構造化 | 入力済み自由記述テキスト | LLM API（OpenAI/Claude）にテキストを送信し、プロンプトで構造化項目を抽出指示 | 構造化JSON（発生日, 設備名, 現象, 原因, 対策, コスト, 停止時間, 故障モード） |
| 構造化結果表示 | LLMから返却された構造化JSON | JSONをパースし、各項目をカード形式にレンダリング | 画面上に各項目が整理されたカード表示 |
| 構造化結果の編集 | ユーザーによる各項目の修正入力 | 編集フォームの値でJSONを更新 | 修正済み構造化JSON |
| データ保存 | 確認済みの構造化JSON | DBにINSERT（故障レコードテーブル） | 保存成功通知、入力フォームのリセット |
| サンプルデータ投入 | サンプル故障報告テキスト群（事前定義、10〜20件） | 各テキストを順次LLM APIで構造化し、DBに保存 | 投入完了通知、投入件数の表示 |

## UI状態遷移

| 要素 | 対応機能 | 状態 |
|------|---------|------|
| テキストエリア | テキスト入力 | 空（初期）→ 入力中 → 入力済み → リセット（保存後） |
| 構造化ボタン | LLM構造化 | 無効（テキスト未入力）→ 有効（テキスト入力済み）→ ローディング（API呼出中）→ 有効（完了後） |
| ローディング表示 | LLM構造化 | 非表示（初期）→ 表示（API呼出中）→ 非表示（完了） |
| 構造化結果カード | 構造化結果表示 | 非表示（初期）→ 表示（構造化完了後） |
| 編集フォーム | 構造化結果の編集 | 読取専用（初期表示）→ 編集可能（項目クリック時） |
| 保存ボタン | データ保存 | 非表示（初期）→ 有効（構造化完了後）→ ローディング（保存中）→ 成功表示 |
| サンプル投入ボタン | サンプルデータ投入 | 有効（初期）→ ローディング（投入中）→ 完了表示 |
